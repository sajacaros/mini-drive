# Phase 8 드라이브 UX E2E 테스트 계획

## Application Overview

mini-drive 프론트엔드 Phase 8(드라이브 UX) 기능 검증. 대상: (1) 파일 변경 실시간 반영(SSE, `GET /api/files/events`), (2) 즐겨찾기(별 토글·즐겨찾기 뷰), (3) 최근 이용 콘텐츠(미리보기/다운로드 기록·최근 뷰·홈 스트립).

## 탐색으로 확인한 사실
- **로그인**: `/login` — 라벨 "이메일"/"비밀번호", 버튼 "로그인". 성공 시 사이드바 "내 드라이브" 링크 노출(seed.spec.ts `loginAsAdmin` 재사용).
- **사이드바 라우트**: `/`(내 드라이브), `/favorites`(즐겨찾기), `/recent`(최근), `/shared`(공유됨), `/groups`(그룹), `/trash`(휴지통), `/shares`(공유 링크), `/admin/*`.
- **빈 상태 문구**:
  - 드라이브 홈: "이 폴더가 비어 있습니다" / "파일을 끌어다 놓거나 업로드 버튼을 눌러 시작하세요."
  - 즐겨찾기(`/favorites`): "즐겨찾기한 항목이 없습니다" / "파일이나 폴더의 별 아이콘을 눌러 즐겨찾기에 추가하세요."
  - 최근(`/recent`): "최근 이용한 항목이 없습니다" / "파일을 미리보거나 내려받으면 여기에 표시됩니다."
- **툴바**: 버튼 "목록 보기"/"그리드 보기"(토글, `pressed` 상태), "새 폴더", "업로드"(네이티브 파일 선택창 오픈).
- **새 폴더 다이얼로그**: heading "새 폴더", textbox "폴더 이름", 버튼 "취소"/"만들기". 토스트: "폴더를 만들었습니다."
- **행 액션(드라이브 홈, hover 시 노출)**: 파일 = 미리보기/다운로드/새 버전 업로드/버전 기록/공유/권한 관리/이름 변경/삭제. 폴더 = 권한 관리/이름 변경/삭제(미리보기·다운로드 없음).
- **즐겨찾기 별 아이콘**: `aria-label`이 "즐겨찾기"(미등록) ↔ "즐겨찾기 해제"(등록, `pressed=true`)로 토글. CSS: 미등록 시 `opacity-0`(그룹 hover 시에만 `opacity-100`), 등록 시 `opacity-0` 클래스 자체가 사라져 **항상 표시**(hover 불필요). 리스트·그리드 뷰 모두 동일하게 지원(폴더 포함).
- **즐겨찾기 뷰(`/favorites`)**: heading "즐겨찾기", 부제 "별표한 파일과 폴더입니다." 목록/그리드 토글 있음. **리스트 뷰는 파일 행에 "다운로드" 버튼만 노출(미리보기·이름변경·삭제 없음), 폴더 행은 액션 버튼 없음** — 반면 **그리드 뷰는 파일 카드에 미리보기+다운로드 모두 노출**. 즐겨찾기 해제 클릭 시 그 자리에서 즉시 행이 사라지고, 마지막 항목이면 빈 상태로 전환(재조회 없이 클라이언트 상태로 반영, 페이지 새로고침 불필요).
- **최근 뷰(`/recent`)**: heading "최근", 부제 "최근에 미리보거나 내려받은 파일입니다." 행은 이름/별/크기/수정(접근)일 + "다운로드" 버튼만 노출(미리보기 버튼 없음, 즐겨찾기 뷰와 유사하게 액션 최소화).
- **드라이브 홈 "최근 항목" 스트립**: 루트 목록 상단에 heading "최근 항목" + 버튼(아이콘+파일명) 카드 노출. 파일이 없으면 스트립 자체가 렌더되지 않음(즉, 헤더+테이블 사이에 조건부 표시).
- **이름 변경 다이얼로그**: heading "이름 변경", 기존 이름이 채워진 textbox, 버튼 "취소"/"변경". 토스트: "이름을 변경했습니다." 변경 즉시 목록 행 + 최근 항목 스트립 라벨이 동시에 갱신됨(재조회 없이).
- **삭제(휴지통 이동) 다이얼로그**: heading "휴지통으로 이동", 본문 "{name} 항목을 휴지통으로 이동하시겠습니까?"(폴더는 "…폴더와 하위 항목을 휴지통으로 이동하시겠습니까?"), 버튼 "취소"/"휴지통으로 이동". 토스트: "휴지통으로 이동했습니다." 확정 즉시 목록에서 사라지고, 그 파일이 "최근 항목"에 있었다면 스트립·`/recent` 뷰에서도 함께 사라짐(삭제된 파일 제외 규칙, 8-3 설계 문서와 일치).
- **휴지통(`/trash`)**: heading "휴지통", 컬럼 이름/크기/삭제일, 행 액션 "복구"/"영구 삭제". 영구 삭제 다이얼로그: heading "영구 삭제", 본문 "{name} 을(를) 영구 삭제합니다. 이 작업은 되돌릴 수 없습니다.", 버튼 "취소"/"영구 삭제". 토스트: "영구 삭제했습니다."
- **SSE 확인**: `GET /api/files/events` 요청이 실제로 200으로 열려 있음(네트워크 탭 확인). 별도 프론트 재조회 호출 없이 업로드/생성/이름변경/삭제 후 같은 탭 목록이 즉시 갱신됨. 진짜 SSE 푸시 경로(내가 아닌 다른 관찰자에게도 push)는 같은 로그인 세션의 두 번째 탭/컨텍스트로 검증 가능(다른 사용자 동시성은 백로그).
- **업로드**: 업로드 버튼 클릭 → 네이티브 파일 선택창(`browser_file_upload`/`setInputFiles`로 처리). 성공 시 저장 용량 표시(사이드바 "0 B / 10.0 GB")도 즉시 갱신.
- 토스트는 화면 하단 `status` role 요소로 노출되고 클릭 가능(자동 소멸 추정).

## Test Scenarios

### 1. 실시간 목록 갱신 (SSE)

**Seed:** `frontend/e2e/seed.spec.ts`

#### 1.1. 업로드 후 목록이 재조회 없이 즉시 갱신된다

**File:** `e2e/sse/upload-reflects.spec.ts`

**Steps:**
  1. loginAsAdmin으로 로그인 후 드라이브 홈(/)으로 이동
    - expect: 빈 폴더 상태 문구 "이 폴더가 비어 있습니다"가 보인다(또는 기존 항목이 있다면 무시)
  2. 테스트 전용 소스 파일(예: 이 테스트가 생성한 임시 텍스트 파일)을 '업로드' 버튼으로 선택
    - expect: 파일 선택 즉시(수동 새로고침·재방문 없이) 목록 테이블에 새 행이 나타난다
    - expect: 사이드바 저장 용량 텍스트(예: "0 B / 10.0 GB")가 증가한다
    - expect: 성공 토스트가 노출된다(예: 업로드 완료 관련 문구)
  3. 테스트 종료 시 업로드한 파일을 삭제(휴지통 이동) 후 휴지통에서 영구 삭제
    - expect: 드라이브가 테스트 시작 전 상태로 복원된다

#### 1.2. 새 폴더 생성 시 목록이 즉시 갱신된다

**File:** `e2e/sse/create-folder-reflects.spec.ts`

**Steps:**
  1. 드라이브 홈에서 '새 폴더' 버튼 클릭 → 다이얼로그의 '폴더 이름' textbox에 고유한 이름(예: e2e-sse-<timestamp>) 입력 → '만들기' 클릭
    - expect: 다이얼로그가 닫히고 토스트 "폴더를 만들었습니다."가 보인다
    - expect: 재조회/새로고침 없이 테이블에 해당 폴더 행이 즉시 나타난다(권한 관리/이름 변경/삭제 액션 포함)
  2. 생성한 폴더를 삭제(휴지통 이동) 후 휴지통에서 영구 삭제하여 정리
    - expect: 드라이브 홈 목록에서 폴더가 사라진다

#### 1.3. 이름 변경이 목록과 최근 항목 스트립에 즉시 반영된다

**File:** `e2e/sse/rename-reflects.spec.ts`

**Steps:**
  1. 테스트 파일을 업로드하고 '미리보기'를 1회 실행해 최근 항목에 등록되게 한 뒤 드라이브 홈으로 복귀
    - expect: 드라이브 홈 상단에 heading "최근 항목" 스트립과 해당 파일명 카드가 보인다
  2. 해당 파일 행의 '이름 변경' 버튼 클릭 → textbox 값을 새 이름으로 변경 → '변경' 클릭
    - expect: 토스트 "이름을 변경했습니다."가 보인다
    - expect: 목록 행의 파일명이 즉시 새 이름으로 바뀐다(재조회 없이)
    - expect: "최근 항목" 스트립의 카드 라벨도 같은 새 이름으로 동시에 갱신된다
  3. 파일을 삭제(휴지통 이동) 후 휴지통에서 영구 삭제하여 정리
    - expect: 드라이브가 정리된다

#### 1.4. 삭제(휴지통 이동) 시 목록에서 즉시 사라지고 최근 항목에서도 제외된다

**File:** `e2e/sse/delete-reflects.spec.ts`

**Steps:**
  1. 테스트 파일을 업로드하고 미리보기 실행하여 최근 항목에 등록되게 함
    - expect: 드라이브 홈에 "최근 항목" 스트립이 파일과 함께 노출된다
  2. 해당 파일 행의 '삭제' 버튼 클릭 → 다이얼로그(heading "휴지통으로 이동", 본문 "{name} 항목을 휴지통으로 이동하시겠습니까?")에서 '휴지통으로 이동' 클릭
    - expect: 토스트 "휴지통으로 이동했습니다."가 보인다
    - expect: 목록 테이블에서 해당 행이 즉시 제거된다(빈 상태라면 빈 상태 문구로 전환)
    - expect: "최근 항목" 스트립 전체가 사라지거나(유일한 최근 항목이었을 경우) 해당 카드가 제거된다 — 삭제된 파일은 최근 목록에서 제외되어야 한다
  3. /recent 로 이동
    - expect: 삭제한 파일이 목록에 없다(전체가 비었다면 최근 빈 상태 문구 "최근 이용한 항목이 없습니다"가 보인다)
  4. /trash 에서 해당 파일을 '영구 삭제'로 완전히 제거
    - expect: 휴지통 목록에서 사라진다

#### 1.5. [핵심] 같은 세션의 두 번째 탭에 SSE로 변경이 자동 반영된다 (수동 새로고침 없음)

**File:** `e2e/sse/cross-tab-live-update.spec.ts`

**Steps:**
  1. 탭 A: loginAsAdmin으로 로그인 후 드라이브 홈(/)에 머무른다. 탭 B: 같은 admin 계정으로 별도 BrowserContext/Page를 열어 동일하게 로그인 후 같은 드라이브 홈(/)에 머무른다
    - expect: 두 탭 모두 같은 폴더(루트) 목록을 보고 있다
  2. 탭 B에서 '새 폴더'를 만든다(예: e2e-sse-crosstab-<timestamp>)
    - expect: 탭 B 목록에 즉시 폴더가 나타난다
  3. 탭 A에서 아무 것도 조작하지 않고(새로고침/재방문 없이) 수 초(예: 최대 5~10초) 대기하며 목록을 관찰한다
    - expect: 탭 A의 목록에도 새 폴더 행이 자동으로 나타난다 — 이는 GET /api/files/events SSE 스트림을 통한 실시간 반영이다(폴링/새로고침이 아님을 네트워크 탭에서 함께 확인 가능)
  4. 탭 B에서 방금 만든 폴더를 삭제(휴지통 이동)하고 휴지통에서 영구 삭제
    - expect: 탭 A에서도 별도 조작 없이 목록에서 폴더가 사라진다
    - expect: 두 탭 모두 정리된 빈 상태로 복귀한다

### 2. 즐겨찾기

**Seed:** `frontend/e2e/seed.spec.ts`

#### 2.1. 즐겨찾기 빈 상태 확인

**File:** `e2e/favorites/empty-state.spec.ts`

**Steps:**
  1. loginAsAdmin으로 로그인 후 사이드바 '즐겨찾기' 링크(→ /favorites)로 이동. 사전에 즐겨찾기한 항목이 없는 상태를 보장(필요 시 기존 즐겨찾기를 먼저 해제)
    - expect: heading "즐겨찾기"와 부제 "별표한 파일과 폴더입니다."가 보인다
    - expect: 빈 상태 문구 "즐겨찾기한 항목이 없습니다" / "파일이나 폴더의 별 아이콘을 눌러 즐겨찾기에 추가하세요."가 보인다

#### 2.2. 행 hover 시 별 아이콘이 노출되고 클릭으로 즐겨찾기 등록 → 즐겨찾기 뷰에 반영

**File:** `e2e/favorites/toggle-add.spec.ts`

**Steps:**
  1. 드라이브 홈에서 테스트 파일을 업로드한다
    - expect: 목록에 파일 행이 나타난다
  2. hover 하지 않은 상태에서 별 아이콘 버튼(aria-label="즐겨찾기")의 opacity를 확인(getComputedStyle 또는 클래스 opacity-0 존재)
    - expect: hover 전에는 opacity가 0(시각적으로 숨김) 이다
  3. 해당 행에 마우스를 hover 한다
    - expect: 별 아이콘이 시각적으로 노출된다(opacity 100 / group-hover 클래스 적용)
  4. 별 아이콘(aria-label="즐겨찾기") 클릭
    - expect: 버튼의 aria-label이 "즐겨찾기 해제"로 바뀌고 pressed 상태가 된다
    - expect: hover를 해제해도(마우스를 다른 곳으로 이동) 별 아이콘이 계속 보인다(opacity-0 클래스가 제거됨)
  5. 사이드바 '즐겨찾기'(/favorites)로 이동
    - expect: 해당 파일이 목록에 나타나고 별 아이콘은 pressed("즐겨찾기 해제") 상태로 항상 표시된다
  6. 테스트 정리: 파일을 삭제(휴지통 이동) 후 영구 삭제
    - expect: 드라이브가 정리된다

#### 2.4. 즐겨찾기 해제 시 즐겨찾기 뷰에서 즉시 사라지고 빈 상태로 복귀한다

**File:** `e2e/favorites/toggle-remove.spec.ts`
